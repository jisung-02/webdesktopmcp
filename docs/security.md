# webdesktopmcp 보안 모델

공식 출처와 구현·테스트별 적용 근거: [레퍼런스](references.md).

검토일: 2026-09-05. 이 문서는 실험적 데스크톱 WebMCP-to-MCP 브리지의 보안 경계를 설명합니다. [WebMCP CG 초안](https://webmachinelearning.github.io/webmcp/)은 W3C 표준이나 표준화 트랙 문서가 아니며, 이 라이브러리가 브라우저의 보안 모델 전체를 구현한다는 의미가 아닙니다. 기능 범위는 [지원 표](support.md)를 기준으로 합니다.

## 라이브러리의 방어와 한계

| 항목 | 동작 및 범위 |
|---|---|
| 로컬 연결 | MCP 서버는 `127.0.0.1`에 바인딩하고 bearer 토큰을 요구합니다. 토큰을 가진 동일 사용자 프로세스는 클라이언트가 될 수 있습니다. |
| 토큰 비교 | Node 호스트는 `crypto.timingSafeEqual`로 같은 길이의 토큰 바이트를 비교합니다. 이것이 전체 HTTP 처리의 상수시간 실행을 뜻하지는 않습니다. |
| 레지스트리 | 로컬 레지스트리에 연결 토큰을 저장합니다. Unix 권한과 Windows ACL은 다르며 파일을 같은 사용자의 악성 프로세스로부터 격리하지 못합니다. |
| 도구 소유권 | 중복 이름을 거부하고 실행/등록 해제를 소유 프레임에 연결합니다. 실제 프레임 식별 보장은 아래 어댑터 경계에 따릅니다. |
| 외부 노출 | 비어 있지 않은 `exposedTo` 목록이 있는 도구는 외부 MCP `tools/list`와 `tools/call` 모두에서 제외합니다. 이는 인페이지 클라이언트용으로 예약하는 **라이브러리 정책**이며 외부 MCP 사용자를 브라우저 origin으로 인증하는 기능이 아닙니다. |
| 사용자 확인 | Electron `confirmToolCall`, Go `SetConfirmHook` 등 호스트 훅으로 앱이 동의를 구현할 수 있습니다. 자동 확인 UI나 모든 부작용에 대한 강제 확인을 보장하지 않습니다. |
| 취소 | 페이지→호스트 취소를 전달합니다. CLI는 호출별 HTTP 연결을 닫아 취소하며 호스트별 연결 종료 처리는 다를 수 있습니다. 별도 HTTP 요청의 `notifications/cancelled`는 활성 호출과 연결하지 않습니다. 모든 클라이언트 취소의 전파를 보장하지 않습니다. 실행 코드는 신호를 관찰해야 하며 이미 발생한 부작용은 되돌아가지 않습니다. |
| 가시성 | 라이브러리는 창의 가시성을 강제하거나 headless 실행을 금지하지 않습니다. 사용자에게 동작을 보여 주는 것은 앱의 책임입니다. |

## 어댑터의 신뢰 경계

신뢰할 수 있는 앱 콘텐츠에만 브리지를 설치하세요. 외부 웹 콘텐츠에 호스트 바인딩을 제공하면 앱 권한으로 도구를 노출할 수 있습니다.

- Electron은 preload와 호스트 IPC 경계를 사용합니다. 지원하는 프레임 라우팅 범위가 브라우저 전체 Permissions Policy 구현을 의미하지 않습니다.
- Tauri는 호스트가 확인한 webview URL을 사용하지만 그 URL로 DOM 하위 iframe의 신원을 인증할 수는 없습니다.
- Wails의 `Send(frameId, message)`는 신뢰된 앱 renderer를 전제합니다. 페이지가 전달한 frameId 자체는 플랫폼이 인증한 신원이 아닙니다. 교차 프레임 origin은 호스트 `SetFrameOrigin`으로 설정해야 합니다. 알 수 없는 origin은 교차 프레임 접근에 사용하지 않습니다.

네이티브 브라우저의 페이지 API와 외부 MCP 브리지는 별도 경로입니다. 네이티브 API가 존재해도 브리지에 브라우저의 모든 origin/iframe 권한 보장이 자동으로 생기지 않습니다.

## 앱과 에이전트가 처리해야 할 위험

1. **입력 검증**: 서버와 폴리필은 도구 인자의 JSON Schema `required`나 `type`을 런타임 검증하지 않습니다. `defineTool`의 TypeScript 타입도 런타임 검증이 아닙니다. 도구 실행 시 입력, 업무 규칙, 사용자 권한을 검증하세요.
2. **프롬프트 인젝션**: 도구 설명과 반환값은 신뢰할 수 없는 데이터일 수 있습니다. 도구 메타데이터나 사용자 생성 콘텐츠를 에이전트의 상위 지시로 취급하지 마세요. `untrustedContentHint`는 방어를 강제하는 장치가 아닙니다.
3. **부작용과 의도**: 결제·삭제 등의 실제 부작용을 설명에 명시하고 필요한 확인을 구현하세요. `readOnlyHint`는 접근 통제가 아닙니다.
4. **개인정보와 로컬 토큰**: 필요한 최소 입력만 수집하고 토큰을 로그나 배포 파일에 넣지 마세요. 동일 사용자 권한의 프로세스는 레지스트리 토큰에 접근할 수 있습니다.

공식 WPT 적합성이나 모든 플랫폼의 네이티브 GUI 보안 검증은 완료했다고 주장하지 않습니다. 저장소의 자동 테스트 범위는 [지원 및 검증 문서](support.md)에 명시합니다.
